# 夜雨竹林成长与战斗表现升级

## 目的与授权

在已有可通关示范上落实参考研究所得的成长决策、流派内部路线和动作表现。用户已确认全部完成并自动进行，沿用此前的子代理执行与主代理整合审查安排；常规设计与计划选择由代理完成，不再次等待阶段确认。此规格补充原夜雨竹林设计，冲突处以本文为准。

## 范围与约束

- 继续使用独立 demo/ ES modules 和本地 Canvas/DOM/WebAudio，无新增产品依赖、远程资源或后端。
- 保留武侠题材、三场景九节点、五次成长、三次本门成长质变、五骰两次重掷。
- 点击选择要换的骰子，选中的一起重掷；未选中不改变；空选择不消耗次数或随机状态。
- 角色、场景、图形和音频原创；不复制参考 APK 的代码或素材。
- 所有规则确定性、纯函数、输入不可变；预览不消耗随机状态。表现只消费事件快照。
- 原版 qipai-jianghu-v1 存档不改；示范键仍为 qipai-bamboo-demo-v1，旧版示范可迁移；设置键不改。
- 支持 360px 窄屏、键盘、静音和减少动态；无横向滚动，不用仅有颜色区分状态。

## 成长流程

奖励仍有三张候选牌。绑定类先选牌，再选五颗骰子之一，显示旧技能和新技能，确认才生效；取消仅清除待选状态，不改技能、次数、随机数和成长统计。分支类无目标骰，显示当前等级与下一等级后确认。待选牌与待选骰保存在可恢复状态中。

新局 version=2，增加 perks（六个分支等级，0–2）与 pendingUpgrade（null 或 {choiceId,dieIndex:null|0..4}）。旧 v1 进度补零级分支和空待选；旧奖励原样保留文字/ID，将 kind=skill 迁移为 bind。迁移不重新投骰或抽牌。无效新存档仍拒绝读取并给提示。

绑定类仍支持三流派，目标同门则技能等级加一，不同门则替换为一级。记录本门成长可达三次质变；绑定与分支都按选择的 build 计入对应成长。保留 chooseUpgrade 的无待选旧调用兼容，但浏览器确认必须要求绑定目标；有待选且未选目标时不能自动落点。

## 六条内部路线

每个分支最多二级，显示前后变化与实际触发条件。仅当至少有该流派绑定骰时进入其候选池。

| ID | 名称 | 每级效果 |
| --- | --- | --- |
| swordFocus | 凝锋 | 每颗触发剑气的骰子额外对当前目标造成3伤害 |
| swordEcho | 回响剑阵 | 每两颗触发剑气骰子额外对全体造成3伤害 |
| poisonLingering | 蚀骨余毒 | 毒持续时间+1回合，每层毒每回合伤害+2 |
| poisonCatalyst | 催毒引爆 | 每次施毒额外附1层；质变毒爆阈值每级降低1，最低4层；每次仍消耗当前阈值层数 |
| guardBulwark | 固若金汤 | 每次护盾触发额外获得2护盾 |
| guardRiposte | 借力反震 | 抵挡后反击每级5伤害；与质变8伤害相加，质变前也可由本分支反击 |

基础技能和首领数值先沿用。候选始终有一张本门绑定牌；第二张从未满级本门分支中确定性抽取；第三张从剩余可用分支与跨门绑定中抽取。分支满级不重复提供；当本门分支全满时从其他合法候选补齐。抽取只在首次创建该批奖励时推进 RNG，恢复/重复渲染不重抽。

## 共用结算的预览

previewAttack 保留 combo/directDamage/triggers/enemyIntents，增加 forecast 和 effects。pick 阶段通过同一 resolveRound 规则进行克隆试算，不维护第二套伤害公式；其他阶段 forecast=null。forecast 包含总伤害、毒伤、阻挡、最终英雄气血与护盾，以及各敌人的最终气血/护盾/毒层。effects 为省略 snapshot 的已知事件摘要。UI分开呈现直接伤害、技能/状态、敌方回应，不把后续毒伤写成直接伤害。

预览不得修改输入或 RNG；已知确定性结算须与实际 state/events 一致。目标改变、骰面改变、技能或分支改变后同步更新。

## 表现事件与动作

保持现有 sourceId/targetIds/value/build/text/snapshot 字段。施毒用 poisonApply，持续毒伤用 poisonTick；凝锋与回响分别用 swordFocus/swordEcho；万剑归宗攻击用 swordArray，且先发 ascension 事件。普通 sword、strike、shield、counter、burst、intent、hurt、death、phase、finish 继续支持。旧 poison 事件按数值0为附毒、大于0为毒伤兼容。

角色新增独立关节姿态、布料/披风层次与武器轮廓；主角和精英/首领有可辨认的准备、释放、命中、收招、受击和死亡姿态。三场景加强不同构图与地面、建筑层次。持续毒伤在敌人身上侵蚀；飞针用于施毒；毒爆独立爆裂；剑阵包含地面阵纹、飞剑层和命中层；金刚为护体、抵挡与反震分开反馈。

controller 向 play(event, {eventIndex,events}) 传整轮上下文，scene.play 接受可选上下文。正常整轮事件时长预算2600ms，按事件权重分配，总和允许2200–3400ms；减少动态更短且取消震屏/大位移/闪白。纯 choreography 模块负责时长与姿态采样，Canvas 只绘制。音频失败/静音不能阻塞播放，结束或销毁解除等待。

## 验收

- 旧51项回归适配必要接口后通过；新增真实行为测试覆盖指定目标、不选/取消、前置/满级、确定性抽牌、旧档迁移与待选恢复。
- 每条分支至少一个可观测机制测试；预览与实际结算比较多个流派/目标/护盾/首领阶段；输入保持不变。
- 三流派、两条路线的固定种子旅程可完成；运行1–100种子模拟并记录胜率/回合，依据失败分布调优，不能只报告最优策略。
- 浏览器真实执行选牌、选骰、返回、确认、预览、重掷、出招和通关；验收360px和桌面，检查控制台。
- 截图展示成长目标与战斗新表现；交付可玩链接、源码压缩包与验证记录。真人首次8–12分钟仍需用户实测，不以脚本时长冒充。
