# 七派江湖 · 全系统玩法与修改指南

本指南对应源码包的 `demo/`：一个可配装、可闯关、可改 JSON 的原创离线工坊。仓库根目录的原版首页仍保留，原版与本版玩法和存档分开。

## 运行与第一局

在解压后的源码包根目录打开终端：

```sh
python3 -m http.server 8768
```

打开 [本地示范入口](http://localhost:8768/demo/)。需要 HTTP，不要双击 `demo/index.html`；无需构建或安装产品依赖。终端按 Ctrl+C 停止服务。

1. 在「江湖门庭」先看兵装、骰匣、武学和奇珍，顶部展示下次出征的属性。
2. 「出征」里选择局内传承、玩法和章节，再点「按当前配装出征」。上方三张传承卡可直接开启常规首章。
3. **进入回合自动掷骰，攻击由你决定。** 点击要更换的骰子，再点重掷；未选中的保留。基础重掷 2 次，配装可增加，最多 6 次。
4. 点击敌人选择目标，查看下方「本回合推演」，再点「出招」。推演包含直伤、技能、毒、敌方回应和预期气血／护盾。
5. 成长时先选武学，再选目标骰并确认；同门升阶、异门替换。路线精进不需要绑定骰，Esc 可返回重选。

快捷键：1–5 选骰、R 重掷、空格执行当前主操作。焦点在按钮或表单时保留原生操作。顶部提供声音、减少动态效果、门庭和暂离。

| 同伴 | **5 灵兽、6 武魂**；1 灵兽出战、最多 3 武魂，另有称号 |

| 经济 | 铜钱、锻材、精华、悟性；行囊、固定街市、软货币抽取、3 类采集、4 配方 |

| 出征 | **7 章、11 模式**，见下表 |

装备操作在「兵装」中完成。强化跟随槽位，换装备保留；「重置返还」每点一次降低一级，默认返还该级全部锻材和一半铜钱。洗练先产生候选，接受后生效；取消保留旧属性，费用不返还。保护、已装备、仍有候选的装备不能分解或作为被消耗材料；合成还需要另一件同模板、未装备／未保护／未镶嵌的副本。分解返还镶嵌宝石。

三类武器改变战斗方式：剑强化顺子；法杖在两对及以上群攻；锤在三条及以上加盾、破坏敌方架势。套装三件效果为原创规则，不是已核实的参考装备套装复刻。

门派决定被动与默认六面；切换门派会重置五骰点数，材质和刻印仍独立保存。物理面编号在工坊为 **0–5**，点数为 **1–6**，同点数可重复。刻印跟随物理面，变纹只参与牌型替代、最多涉及两颗骰；连环装饰只扩展一层邻骰，不无限连锁。冻结／定心骰的限制会显示在战斗界面。

符文「合成升阶」是消耗本地资源提高已有符文等级，**不含参考完整的重复星石合成与随机词条洗练**。遗物为最多三件、牌型阶位触发追加伤害及原创三件共鸣；支持洗练候选和灌注，未接入参考全部词条锁定、分解与品质共鸣规则。

## 进度、药品和返回门庭

- **出发快照：** 配装、骰匣、武学、路线倍率与模式参数在新局保存。门庭改装、导入内容或档案后，继续旧旅程不会换成新配装；要体验改动请新出征。
- **回门庭：** 保留旅程，可用「继续已保存旅途」恢复；已有待选骰不会再随机投一次。
- **新出征／再入江湖：** 放弃尚未完成的旧局，扣已用药品、不给放弃奖励，然后按新配装出发。不是同时保存多条旅程。
- **药品：** 回气散回复 35；转运签加一次重掷（总量上限 6）；解毒丸回复 15、加 5 盾并清已有毒；养元露使本次旅程攻击 +3。它们先作用于局内行囊，结束或放弃时再与门庭库存结算，不能靠回门庭免除消耗。
- **一次结算：** 正常出征生成递增的数字 `runId`，`settledRunIds` 记录已发奖编号，防重复恢复／渲染领奖。不要手改 `nextRunId` 或已结算记录。
- **三星扫荡：** 默认一星通关，再分别以剩余气血 ≥40%、累计交锋 ≤18 回合多得一星；三星后才可消耗铜钱扫荡。
- **任务与时间：** 六类任务累计达标后各领取一次；每日行路礼按本机时间的 UTC 日序号领取；未实现参考的完整周任务重置。离线所得按完整小时计算，默认最多 12 小时，领取后重设计时，时间倒退不产生收益。

本版使用浏览器 localStorage，无云同步。同一浏览器的不同域名或端口有不同存档。原版键 `qipai-jianghu-v1` 保留；本版档案为 `qipai-bamboo-profile-v1`，旅程为 `qipai-bamboo-demo-v1`，声音／动态设置另存。旧示范旅程经校验迁移到内部 v3。

## 自己修改：先导出，再小步改

「修改工具」有两种 JSON：

| 导出项 | 包含什么 | 对应导入 |
|---|---|---|
| 将内容配置写入文本 | 名称、目录、效果、成本、奖励、章节／模式数值、经济规则 | 校验并应用内容 |
| 将档案写入文本 | 个人资源、装备实例、配装、修炼、领取记录及内容覆盖 | 校验并导入档案 |

按钮把完整 JSON **写入文本框**，不会自动下载。选中文本框全部内容，复制到文本编辑器另存为 `.json`。分别留一份不改的备份；不要把两类 JSON 混用。档案导出不含进行中的旅程，不能将它当作所有旅程的迁移备份。

推荐流程：

1. 先保存 `档案备份.json` 与 `内容备份.json`。
2. 导出内容，只改一两项；保持完整外层对象与 `version: 1`。
3. 粘贴回文本框，点「校验并应用内容」。失败会显示字段原因，旧配置和档案保留。
4. 新出征观察结果；当前旅程保持出发快照。
5. 不满意时重新导入备份。也可点「恢复默认内容配置」；若档案引用自订条目而不兼容会拒绝恢复。恢复内容不会重置个人资源。

常改字段：

| 想改什么 | 字段与约束 |
|---|---|
| 中文名称、说明 | 对应条目的 `name`、`description`；名称不为空，不写 HTML |
| 装备／天赋／武魂等加成 | 已有 `effects`，如 `attack`、`maxHp`、`armor`、`critChance`、`poisonDamage`、`shieldGain`、`extraRerolls`、`regen`、`goldBonus`；用已支持效果键和非负有限数 |
| 武学触发效果 | `skills[].effects` 的 `damage`、`heal`、`shield`、`poison`、`attack`；`trigger` 只用已有关键字 |
| 消耗与收益 | `cost`、`upgradeCost`、`refineCost`、`reward` 等；资源名为 `gold`／`dust`／`essence`／`insight`，数量用非负整数 |
| 章节难度 | `chapters[].hpScale`、`attackScale`，必须为正数；模式也有同名倍率，两者相乘 |
| 回合上限 | `modes[].turnLimit`：**1..1000 整数** |
| 离线封顶 | `economy.offlineHours`：默认 **12**，可设 **1..100 整数** |
| 离线速率 | `economy.offlineGoldPerHour`、`offlineDustPerHour`：非负整数 |

例如把完整 JSON 中 `chapters` 的 `bamboo` 条目改为 `"hpScale": 0.8`、`"attackScale": 0.8`；把 `resource` 模式的 `"turnLimit": 8` 改为 `12`；把 `economy` 的 `"offlineHours": 12` 改为 `24`。这些只是要修改的字段示例，不能用残缺片段覆盖整个文本框。

先保持所有 ID、目录结构与交叉引用。固定枚举尤其不能增删／改 ID：六槽、材质、装饰、刻印、模式、剑／杖／锤、技能触发关键字与阴阳符文类别。可以改它们的显示名称，但**改描述不会创造新机制**。若要新增材质处理器、模式或效果，需修改源码并扩充校验，不是只添一条 JSON。

档案可改资源、等级等已有字段，但必须通过档案校验。优先用门庭操作或「领取测试补给」，避免手工改装备 `uid`、引用、随机种子、时间戳、数字出征编号和领奖凭据。JSON 仅作为数据读取，不执行脚本。

## 接入边界

本版根据 34 类静态参考证据与原有玩法做原创离线接入。没有解出参考的全部配置表，没有运行参考 APK，没有复制参考代码／美术；价格、概率、配方、套装、章节、模式等采用本地原创数值或简化规则。

真实联机、服务器支付／广告、账号同步、真人聊天／好友／公会、全球排行榜未接入。本地论剑与本地世界首领都不联网。这是可玩、可修改的系统工作台，不是完整同款商业游戏，也不表示参考所有系统已复刻。逐项来源与接入程度见同目录的《六六英雄-系统拆解与接入清单》。
